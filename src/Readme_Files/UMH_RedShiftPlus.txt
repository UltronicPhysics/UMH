UMH Redshift Simulation — README
================================

Published reference: A. Dodge, “Pantheon+ and Redshift Observational Analysis of the UMH Redshift Formulation,” Reports in Advances of Physical Sciences 8 (2026) 2650012, DOI 10.1142/S242494242650012X.

Purpose
-------
This simulation implements the Ultronic Medium Hypothesis (UMH) redshift model, in
which cosmological redshift is generated by tension in a pervasive medium rather
than by metric expansion. The code demonstrates that a *non-expansion* model can 
reproduce the Pantheon+ supernova Hubble diagram while implementing the standard
δ=1, S(z)=1+z time-dilation scaling used in the Hubble-diagram relation.
This analysis does not constitute an independent fit to supernova
light-curve stretch measurements. The script supports fixed or recovered transmission coefficients through `BETA_MODE`.
In `calibrate` mode, β1 and β2 are estimated from the SN data and then held fixed
in the conditional final Hubble-diagram likelihood. In `fixed` mode, configured
β1 and β2 are used directly. In `auto` mode (default), configured fixed values
are used when both are present; otherwise the script falls back to calibration.
Only M0 is profiled in the conditional final likelihood.

Core UMH ingredients
--------------------
1) **Tension-driven redshift law**
   - Distance `d` → redshift `z` via
     [ z(d) = exp(α d) − 1,   L ≡ ln(1+z) = α d. ]
   - `α` is calibrated at low z from distance–redshift calibrators.

2) **Time-dilation and transfer function**
   - Physical time-stretch (light-curve dilation):  S(z) = (1+z)^δ.
     *UMH expectation:* δ = 1 (i.e., S = 1+z, same as SN Ia observations / GR).
   - Broadband spectral/photometric transfer function along the path:
     [ T(z) = exp( −β1 L − β2 L^2 ),  L = ln(1+z). ]
   - In the distance modulus, this enters multiplicatively as 1/√T(z) (i.e., an effective dimming/brightening).
   - Strategy: keep δ fixed at 1, estimate β1 and β2 in the transmission-calibration stage, 
     and then hold them fixed when evaluating the conditional final Hubble-diagram likelihood.
     If β is *fixed to zero*, the fit compensates by drifting δ>1 — a useful diagnostic but 
     not the preferred model.

3) **Luminosity distance and Hubble diagram (no expansion)**
   - Invert z→d under UMH (d = L/α). The model luminosity distance:
     [ D_L(z) = κ · d(z) · (1+z)^{(1+δ)/2} / √T(z). ]
     Here κ is an overall scale absorbed into the profiled magnitude/intercept `M`.
   - Distance modulus:  μ(z) = 5 log10[D_L(z) / (1 Mpc)] + 25.

Data & fitting
--------------
• **Calibrators (low-z, SH0ES/Pantheon+ subset):**
  - We fit **distance vs. log-redshift** with an intercept:
        d = c0 + c1 * L,   where L ≡ ln(1+z), for z ≤ 0.10.
  - **Weights:** distance uncertainties, w = 1/σ_d²; solved with **Huber IRLS** (c ≈ 2.0).
  - We report **α = 1/c1** and (for reference) **H₀ = c · α**.
  - Output files:
      • `UMH_RedShift_Calibration_Data.csv`
      • `UMH_RedShift_Calibration_Fit.json` (α, H₀, c0, c1, χ²/dof, N, and method flags).
  - *Note:* Earlier runs used a through-origin fit of L vs d at z ≲ 0.08 with σ_L weights; this README reflects the updated (Pantheon-matched) procedure.

• **Pantheon+ SNe (SN-only):**
  - Uses the provided STAT+SYS covariance; **M** is profiled (analytically minimized via Cholesky).
  - Two fits are contrasted:
      (A) **δ free, β fixed to 0**  → diagnostic; δ tends to drift > 1 to absorb curvature.
      (B) **δ = 1, β recovered/profiled during the calibration diagnostic**
          → preferred transmission-calibration configuration. 
          The recovered β values are then held fixed in the conditional final likelihood.
  - Fit quality is reported as **χ²/dof**.

Key outputs / numbers to cite
-----------------------------
• **Calibration (this run):** α = (2.48 ± 0.08) × 10⁻⁴ Mpc⁻¹  →  H₀ = 74.40 km s⁻¹ Mpc⁻¹  
  (z ≤ 0.10, with-intercept, Huber IRLS c=2.0, weights 1/σ_d², N=77, c₀ ≈ +1.337 Mpc, χ²/dof ≈ 0.340; see log/JSON). 

• **Pantheon+ fits:**  
  – With **β=0** (diagnostic), best δ ≈ 1.300, χ²/dof ≈ 0.902.
  – In the **δ=1 β-recovery diagnostic** (γ, β₂), χ²/dof = 0.898; the selected final β path is controlled by `BETA_MODE`.

What this demonstrates for UMH
------------------------------
1) A **non-expansion** redshift law (UMH z(d)) calibrated locally reproduces the Pantheon+
   Hubble diagram across the full redshift range.  
2) The preferred UMH configuration retains δ=1, corresponding to S(z)=1+z, the standard time-dilation 
   scaling used in the Hubble-diagram relation. This is not an independent fit to
   supernova light-curve stretch measurements. 
3) The gentle broadband curvature demanded by the data is captured by **T(z)** via the β’s
   (a path-integrated transfer), not by altering δ.  
4) Residuals show **no systematic trend with redshift** once β’s are profiled, confirming
   the internal consistency of the UMH treatment.

Knobs & reproducibility 
-----------------------
- Low-z calibration window: `zmax` (default 0.10) and `dmax` (default 120 Mpc).
- Intercept toggle: `force_through_zero` (default False → fit d = c0 + c1·L).
- Robust regression: Huber IRLS `huber_c` (default 2.0), `max_iter` (default 50).
- Measurement weights for α: distance-domain, `w = 1/σ_d^2` (default).
- PV floor (σ_L): default 200 km/s — used only in L-domain diagnostics/plots, not in the α fit.
- Transmission-coefficient selection: `BETA_MODE="fixed"` requires configured fixed values;
  `BETA_MODE="calibrate"` recovers β1 and β2 from Pantheon+; `BETA_MODE="auto"` uses
  configured fixed values when both are present and otherwise recovers them. β=0 remains
  the diagnostic δ-scan. In the conditional final likelihood, the selected β1 and β2 are
  held fixed and only M is profiled.
- Reproducibility: the calibration JSON records `c0`, `c1`, α (=1/c1), H₀, χ²/dof, N, and all method flags; 
  all plots and the calibration CSV/JSON are written under the run’s output prefix.
